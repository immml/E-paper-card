## 一、为什么值得做

电子贺卡这个品类失败了很多年，原因只有一个：**LCD 一断电就白屏**。
想让它一直亮着，就得一直插电；一插电，它就不再是"一张卡片"，而是"一件电器"。

墨水屏把这个问题反过来解决了：

| 特性 | 带来的产品能力 |
| --- | --- |
| **双稳态，掉电保图** | 写完内容拔掉电源放一年，画面还在。可以真的"递过去" |
| **反射式，无背光** | 靠环境光阅读，纸质感、护眼，不刺眼、不违和 |
| **只在翻页耗电** | 一颗 1000mAh 电池 + 每天刷一次，续航以「年」计 |

于是这张卡可以做到：**平时完全断电，只有翻页那几秒才通电**。
它有了纸的形态，却没有纸的浪费 —— 内容随时可换，硬件一次投入，礼物每年重送。

这也是"不但是贺卡，还是礼物"的落点：
**送出去的是硬件，送不完的是内容。**

## 二、六种形态

### 1. 贺卡模式

- 墨水屏显示祝福图文（**16 级灰度 / 黑白**，抖动作层次）
- 内置 RTC，到点自动翻页：生日当天、跨年零点、纪念日
- 手机 BLE 推图推文，送礼的人不需要会写代码

### 2. 名片模式

- 屏上呈现姓名/职务/二维码，扫一扫加微信
- 板载 NT3H2111 NFC 标签，支持"手机碰一碰"，**无源工作，卡没电也能被读**
- 名片信息走 vCard 格式，安卓 / iOS 原生识别
- 屏长宽比 240 : 416 ≈ 名片 54 : 90 —— **这块屏天生就是名片的外形**

### 3. 电子书模式

- TF 卡读取 TXT / EPUB（转 TXT 预处理），支持 UTF-8 中文
- 16×16 点阵下一行 15 字、一屏 26 行，约 **390 字/屏**，一页正文一屏放得下
- EC11 旋转编码器翻页 + 按键返回，单手操作
- 记录阅读进度到 NVS，断电续读
- 屏保式低刷新策略，一页电耗约等于无

### 4. MP3 模式

- TF 卡扫描音乐文件，墨水屏显示曲名 / 进度（省电的"播放器屏幕"）
- I2S + MAX98357A 直推 3W 喇叭，或走 3.5mm 耳机口
- 支持"贺卡语音"：随卡录一段人声祝福，比文字更重

### 5. AI 听记

> 一句话：**一支能把纪要写到墨水屏上的录音笔。**

先把边界说清：ESP32-S3 **跑不了中文 ASR 模型**，所以听记是
**"高质量采集 + 云端转写"**，本机负责采集、编码与留存。

**两种模式，按供电状态选：**

| | 分时模式（默认 · 电池供电） | 实时模式（插电用） |
| --- | --- | --- |
| WiFi | **全程关闭** | 常开，流式上传 |
| 转写 | 事后批量 | **边说边出** |
| 电流 | ~65 mA | ~170 mA |
| 续航 | 12 ~ 16 小时 | 5 ~ 6 小时 |

**分时模式流程**：按下录音键 → INMP441 采样（16 kHz / 16 bit / 单声道）→ Opus 编码 @16 kbps
（1 小时仅 7.2 MB，比裸 PCM 省 16 倍）→ 写 TF 卡，每 5 分钟一段 —— **全程 WiFi 关闭**；
再次按下停止 → 墨水屏显示「已录 42 分钟 · 9 段 · 待转写」→ 插入 USB 充电时批量上传
→ 服务端转写 → 纪要回写墨水屏 / 推送到手机。

实时模式把「写卡 → 事后上传」换成「流式上传 ↔ 落卡兜底」。
✅ **本项目为黑白版（B/W）** —— 局刷 0.5 s 完全跟得上语速。
**按语义句刷新是设计选择**（逐字刷频次过高、加速屏体老化），不是速度限制，详见 4.4。

**耗电**：分时模式约 65 mA ⇒ 1000 mAh 可录 **12 ~ 16 小时**。

**TF 卡会不会被写死？不会 —— 但风险不在写入量上。**

```
Opus 16 kbps = 2 KB/s = 7.2 MB/小时     24/7 连录一年 ≈ 63 GB
```

| 卡 | 标称 TBW | 折算连续录制 |
| --- | --- | --- |
| 普通消费卡（保守按 10 TB 估） | 10 TB | **158 年** |
| SanDisk High Endurance 128 G | ~40 TB | **634 年** |
| Samsung Pro Endurance 128 G | ~820 TB | 13,000 年 |

即使退到裸 PCM（115 MB/小时，是 Opus 的 16 倍），40 TB 也够写 **39.7 年**。
⇒ **写入总量不是问题，卡只会被容量淘汰，不会被写死。**

**真正会杀死卡的是这两件事，都得靠固件解决：**

1. **FAT 表损坏（头号杀手，与写入量无关）**。监控 / 行车记录仪领域的共识是：
   用户说的"卡坏了"，多数其实是 FAT 被写坏，**重新格式化就能救**；
   触发点是写入中断电、直接拔卡。对策：**只追加不改写**（append-only）、
   分段落盘（坏一段不牵连全部）、VBAT 掉电预警、开机自检自动重建 FAT。
2. **写放大（比总写入量重要得多）**。SD 卡内部 FTL 按页管理，
   若每 20 ms 写一帧 Opus（约 40 字节），实际擦写量可能是逻辑写入量的几十倍。
   对策：**缓冲成 32 ~ 64 KB 大块顺序写**。这一条的差别是"600 年"还是"2 年"。

实时模式下 TF 卡的角色变成**「本地留存 + 断网兜底」**，建议双写（落卡与上传并行）：
断网时继续落卡并标记"待补传"，联网后按段补传。

### 6. 语音助手

> 说明：ESP32-S3 **不能**本地跑大模型。这里是"联网终端"而非"本地推理"。

- **触发**：**按键**（这条是硬约束，理由见下）
- **链路**：INMP441 采样 → Opus 编码 → WebSocket 实时上传 →
  服务端流式 ASR → LLM → TTS → 一路流回设备
- **输出**：文字回答渲染到墨水屏（长文自动分页）；语音由 I2S + MAX98357A 播报
- **交互态**：墨水屏**局刷**显示「聆听 / 思考 / 播报」三态，不全屏闪

> 典型场景：把它立在书桌上，按一下问"今天广州要下雨吗"，
> 墨水屏刷出答案 —— 一次刷新，答案停在那里一整天，不闪不滚。

**⚠️ 语音唤醒不能常开 —— 这是本项目一条硬边界**

唤醒词检测（ESP-SR / WakeNet）要运行，CPU 就必须保持在工作状态；
而 deep sleep 下 CPU 是停的 —— 两者无法同时成立。
实测唤醒词常开监听约 **12 ~ 15 mA**：

| 状态 | 电流 | 1000 mAh 续航 |
| --- | --- | --- |
| 深睡待机（贺卡模式） | ~0.05 mA | **12 ~ 20 个月** |
| **语音唤醒常开** | ~15 mA | **2.7 天** ⚠️ |
| AI 听记（录音中） | ~65 mA | 12 ~ 16 小时 |
| 语音助手（对话中） | ~177 mA | 5 ~ 6 小时 |

**常开唤醒比深睡待机耗电 300 倍**，会把一张能用一年的卡变成三天一充的设备。

同架构商用产品可交叉验证：M5Stack「小智墨伴」（ESP32-S3 + 2.7" 墨水屏 + 麦克风 +
扬声器 + 300 mAh）标称 Wi-Fi 联网待机 3 小时 15 分，唤醒对话电流 177 mA —— 同一量级。

⇒ **结论：助手用按键触发。** 两个例外，都不进首版 BOM：
插着 USB 时可开唤醒词常开（"桌上模式"）；真要"喊一声就醒"，
需加一颗低功耗语音协处理器。

### 3.2.2 这块屏对产品形态的三个影响

**① 240×416 竖版 ≈ 名片比例，产品形态直接立住了**

```
屏    240 : 416 = 1 : 1.73
名片   54 :  90 = 1 : 1.67
```

几乎重合。这张卡天生就是一张名片的外形，竖版持握 ——
"名片模式"不用为屏幕形状做任何折衷，这是选这块屏最大的收益。

**② 电子书模式从"勉强能看"变成"真能用"**

```
每行字数 = 240 / 16 = 15 字
每屏行数 = 416 / 16 = 26 行
一屏容量 ≈ 390 字
```

**③ 帧缓冲只要 12.5 KB，反而放松了主控选型**

```
1-bit 单色：240 × 416 / 8 = 12,480 B ≈ 12.2 KB（双缓冲 ≈ 24.4 KB）
```

ESP32-S3 内部 SRAM 有 512 KB，**帧缓冲根本不需要 PSRAM** ——
所以主控选 N16R2 而非 N16R8，用 2MB Quad PSRAM（对音频与 TLS 足够）
换回 GPIO33~37 这 5 个可用引脚。

### 3.3 GPIO 参考分配

> 以下为规划值，**实际以最终原理图为准**。

| 功能 | 信号 | GPIO | 备注 |
| --- | --- | --- | --- |
| E-Ink | SCK / MOSI / CS / DC / RST / BUSY | 12 / 11 / 10 / 9 / 8 / 7 | SPI2 (FSPI) |
| microSD | CS | 13 | 与墨水屏共用 SPI2 |
| I2C | SDA / SCL | 4 / 5 | AHT20 + PCF8563 + NT3H2111 |
| I2S | BCLK / LRCK / DIN / DOUT | 15 / 16 / 18 / 17 | DIN=麦克风，DOUT=功放 |
| 按键 | KEY1 / KEY2 / KEY3 | 1 / 2 / 47 | 上拉，按下拉低 |
| EC11 | A / B / SW | 41 / 42 / 48 | 编码器 |
| 电池检测 | ADC1_CH5 | 6 | 分压 1/2 |
| **唤醒源 1** | RTC INT | 14 | PCF8563 闹钟中断，**EXT1 唤醒** |
| **唤醒源 2** | KEY1（复用） | 1 | **RTC GPIO，EXT1 唤醒** —— 按键开机 |
| **唤醒源 3** | CHG_DET | 21 | ETA6098 `STAT` 脚（开漏，充电时低），**插 USB 即唤醒**。**须配 10 kΩ 上拉** |
| **电源控制** | 5V_EN | 33 | 控 TPS61023 的 EN，深睡时拉低关断功放轨 |

> ⚠️ **唤醒引脚必须在 RTC GPIO 域**（ESP32-S3 为 GPIO0~21）。上面三个唤醒源
> （14 / 1 / 21）都在域内。GPIO42~48 段**不在 RTC 域**，不能当深睡唤醒源 ——
> 所以按键不能随便挪。

**必须避开的引脚（ESP32-S3 硬件约束）**

| 引脚 | 冲突原因 |
| --- | --- |
| GPIO 0 / 3 / 45 / 46 | Strapping 引脚，上电电平决定启动模式，**不可随意挂外设** |
| GPIO 19 / 20 | USB D- / D+，占用后无法用原生 USB 烧录与 CDC |
| GPIO 26 ~ 32 | 内部 SPI Flash 专用 |
| **GPIO 33 ~ 37** | 选 **R8（Octal PSRAM）会被占用**；本项目选 N16R2（Quad），这 5 个脚可用 |

> 这是 ESP32-S3 最容易踩的坑：照 Quad PSRAM 的例程接 GPIO33-37，
> 换成 R8 模组后功能莫名失效。**选模组前先确认 PSRAM 是 Octal 还是 Quad。**

### 3.4 电源与续航

先把每一项落到规格书数字上：

| 项 | 数值 | 来源 |
| --- | --- | --- |
| ESP32-S3 深睡（RTC 存储 + 外设上电） | **8 µA** | WROOM-1 规格书 表 10 |
| PSRAM 深睡附加（2 MB Quad, 3.3 V） | **40 µA** | 同上注 1 —— **能否断电必须实测** |
| 3.7" 屏休眠 | **≈ 0.9 µA** | 0.003 mW @3.3 V，同规格族面板 |
| PCF8563 走时 + AHT20 休眠 | 0.5 µA | 器件手册典型值 |
| 电池保护板静态 | **3 µA** | PCM 典型值 |
| **ETA6002 电池侧（充电+路径）** | **≤5 µA**（待实测） | datasheet 只给 BATT→IN 漏电 0~5 µA。⚠️ **70 µA 那条是从 VBUS 取的，不花电池的电** |
| **TPS3839 欠压监测（第 2 层）** | **0.25 µA** | datasheet：IQ ~250 nA |
| **TPS62840 Buck 3.3V（空载）** | **0.06 µA** | datasheet：IQ **60 nA** |
| **TPS61023 Boost 5V** | **~0 µA**（可 EN 关断） | IQ 20 µA，但**深睡时用主控 GPIO33 拉 EN 彻底关断** |
| 单次全刷（2 s，含主控等 BUSY） | **≈ 0.022 mAh** | 屏 18 mW×2 s + MCU 35 mA×2 s |

> 新加的三颗 IC 合计只增加 **0.31 µA**，可忽略 —— 这正是选型的意义。
> 同样功能若用 AMS1117（5 mA）+ IP5306（50 µA），整机待机会从 12.4 µA 涨到 5000+ µA，
> **续航直接从"年"掉到"天"**。

待机因此有两个值，差在 PSRAM 那 40 µA：

```
乐观（PSRAM 深睡断电）  17.7 µA × 24 h ≈ 0.42 mAh/天
保守（PSRAM 未断电）    57.7 µA × 24 h ≈ 1.39 mAh/天
```

**但真正的大头是电池自放电，不是电路：**

```
Li-Po 自放电   优质电芯 1~3 %/月，普通 3~5 %/月
              广州夏季 >30 ℃ 会翻倍到 4~6 %/月
按 3 %/月   1000 mAh × 3% / 30 ≈ 0.99 mAh/天
            ← 比整套电路的待机功耗（0.30 mAh/天）还大 3 倍
```

贺卡模式（挂墙/摆桌，每天刷 1 次）日耗：

```
0.30（待机）+ 0.022（刷新）+ 0.99（自放电） = 1.31 mAh/天
1000 mAh × 85%（截止 3.4 V 前的可用容量）/ 1.31 ≈ 649 天 ≈ 21 个月
保守档（PSRAM 未断电）                         ≈ 375 天 ≈ 12 个月
```

**⇒ 正常使用约 12 ~ 20 个月。对外统一说「充一次用一年以上」。**
广州夏季高温把自放电推到 5 %/月，全年平均实际落在 **12 个月上下**。

各模式续航（同一套公式，只换使用强度）：

| 使用方式 | 日耗 | 续航（常温） |
| --- | --- | --- |
| **贺卡（每天全刷 1 次）** | ~1.3 mAh | **12 ~ 20 个月** |
| 电子书（每天读 50 页） | ~1.5 mAh | 11 ~ 18 个月 |
| 语音助手（每天 10 轮，纯文字） | ~5.6 mAh | 5 ~ 6 个月 |
| 语音助手（每天 10 轮，含语音播报） | ~9.8 mAh | 2.5 ~ 3 个月 |
| MP3（每天听 1 小时） | ~194 mAh | **4 ~ 5 天** |

**AI 功能要单独用「连续工作」口径算** —— 听记与对话天然是"一次连着用几小时"的形态，
摊到天上没有意义：

| 连续工作 | 电流 | 满电续航 |
| --- | --- | --- |
| **语音唤醒常开待机** | ~15 mA | **2.7 天** ⚠️ |
| AI 听记（录音 + Opus 编码 + 写卡，WiFi 关） | ~65 mA | **12 ~ 16 小时** |
| 语音助手（对话中，WiFi 连 + 流式） | ~177 mA | 5 ~ 6 小时 |

> **注**：本机的设计目标是**静态（每天刷新 1 次）1 个月、AI 听记 1.5 天**。
> 静态侧实测余量极大（12~20 个月，超目标 12~20 倍）；
> **听记 1.5 天是唯一尚未达成的项** —— 65 mA 只能撑 13 小时，需要把听记电流压到 ≤23.6 mA
> 才成立，这是后续固件优化的主攻方向。

**⇒ AI 是"按需使用"的能力，不是"常开待机"的能力。**
贺卡状态一年一充，一旦要用 AI 就是小时级消耗 —— 这两件事必须在使用说明里讲明白，
否则用户会拿"说好用一年"来质问"为什么开着助手半天就没电了"。

两个反直觉的点：

- **电子书模式几乎不影响续航。** 翻 50 页/天只比贺卡多 0.2 mAh/天 —— 局刷一次才 0.0035 mAh，
  在自放电面前不值一提。墨水屏的"省电"是真的省。
- **MP3 是唯一的耗电怪兽。** 功放是全机唯一持续大电流负载，听 1 小时 ≈ 用掉贺卡模式 150 天的量。
  **宣传里别把 MP3 和"超长续航"放进同一句。**

关键设计点（按重要性排序）：

- **PSRAM 深睡电流必须实测。** 2 MB Quad PSRAM 对应 40 µA，是整机待机假设的 3 倍。
  ESP32-S3 支持深睡时关掉 VDD_SPI 给 PSRAM 断电，但必须用 IDF 配置 + 万用表实测确认，
  不能默认它会自己关。这是第一优先级台架验证项。
- **主控待机是第二战场。** 屏休眠仅 0.9 µA，而板上任何一根 10 kΩ 上拉到 3.3 V
  就是 **0.33 mA —— 屏休眠电流的 360 倍**。能去的外围上拉全去掉，按键改用 MCU 内部上拉。
- **屏供电不要自己切 —— 原设计里那颗 MOS 开关已删掉。** 依据是规格书：
  **第 13 节 AC Characteristics 通篇只有 SPI 时序，没有 power-off sequence**，
  "怎么安全断电"厂商没定义；而屏自身深睡只要 **≤3 µA**。
  挂一颗 MOS 斩屏 VDD 最多省 0.072 mAh/天（**占日耗 5.5%**，且 3 µA 是 Max），
  却要在 VCOM/VGH/VGL 带电状态下去切 VDD —— 风险远大于收益。
  ⇒ **结论：屏 VDD 常接，靠命令让它进深睡。**
- 取消一切常亮 LED（唯一例外：充电指示灯，插电时才亮）。
- RTC 中断唤醒而非主控定时器唤醒，主控平时进入真深睡。

**电源系统六项职责分工（别指望一颗 IC 全包）**

选型时最容易犯的错，是以为"加了充电 IC 就万事大吉"。实际是六件事、六个负责方：

| 职责 | 负责方 | 本项目选择 |
| --- | --- | --- |
| **充电**（恒流恒压 / 输入 OVP） | 充电 IC | **ETA6098** —— BAT 静态 **1 µA**、32V 耐压、电流可调 |
| **电芯保护**（过放/过流/短路） | **电池自带 PCM（第 1 层）** | 502080 出厂带保护板（过放截止 3.0V） |
| **系统保护**（欠压锁断收尾） | **TPS3839（第 2 层）** | **IQ ~250 nA**，3.2V 拉主控 EN，让系统稳定收尾 |
| **稳压**（5V / 3.3V 双轨） | Buck + Boost | **TPS62840** + **TPS61023**，见下方 |
| **睡眠 / 唤醒**（轨开关 + 唤醒源） | 主控 GPIO + RTC 域中断 | **★ 本轮新增**，见下方 |
| **瞬态峰值缓冲** | **缓冲电容** | **220~470 µF 低 ESR**（见下方过流风险） |

**⚠️ 关键缺口：ETA6098 是充电器，不是电池保护器。**
其 datasheet 有 OVP、有 1 µA 静态电流，但**没有任何过放电保护功能**——
防止电池被放空完全依赖电池自带的 PCM。

**★ 充电 IC 能力边界（回原始 datasheet 逐页核对）**

| 能力 | 有 / 无 |
| --- | --- |
| 32 V 输入耐压 + OVP（60 ns 响应） | ✅ |
| BAT 静态电流 **1 µA** | ✅ |
| 充电电流可调（RISET：82KΩ→2A，150KΩ→1.2A） | ✅ |
| 充电温度调节 85 ℃ / 热关断 150 ℃ | ✅ |
| **电源路径管理（Power Path / DPM）** | ❌ **无** |
| **反接保护** | ❌ **无** |

> ⚠️ **更正一条流传的错误说法**：中文技术站写 ETA6098 "内置动态电源路径管理（DPM）"，
> **这是错的** —— 回原始 datasheet 核对，无此描述，也**无 SYS/SYSOUT 引脚**。
> `PMID` 只是"内部 OVP 与充电器之间的连接点"（datasheet 原文），要求接 22 µF 到地，
> **不是给系统供电的输出口**。

> **`STAT` 引脚是开漏输出**（充电时拉低、充满后高阻）。若用它做插电唤醒源，
> **必须配 10 kΩ 上拉**（datasheet 典型应用图用 1 kΩ，充电时会白耗 3.3 mA）。

**★ 电池与系统的关系：选用「在线互动式」**

这块卡该按 UPS 的哪种模式做？三种模式映射到本机：

| UPS 术语 | 本机对应 | 系统电从哪来 | 插 USB 时电池 |
| --- | --- | --- | --- |
| **后备式** | 电池经 MOS / 二极管**隔断**，VBUS 优先 | max(VBUS, BAT) | 完全静置 |
| **在线互动式** ← **本项目** | **电池常挂系统节点，充电器并联补差** | 电池节点 | 边充边供，突发时出力 |
| **在线式** | 系统永远吃电池，USB 只充电 | 电池 | 持续微充微放 |

**选在线互动式，三条理由：**

1. **本机是"极低平均 + 偶发大突发"**（深睡 12.7 µA / 突发 1 A）。
   **电池是天然的峰值缓冲，把它隔断等于在最需要它的时刻切掉它。**
2. **后备式会把 1 A 突发全压给 VBUS** —— 用户可能用老 USB 2.0 口（500 mA）或弱充电宝。
   在线互动式下突发由**电池 + 充电器共同承担**。
3. **纯在线式没必要** —— 系统完全依赖电池，电池老化即整卡报废；
   且插 USB 时电池持续微充微放，长期插电使用会加速老化。

**最终电路（ETA6002 一颗把"充电 + 动态路径"都做掉，不需要任何 OR 电路）：**

```
USB-C ──► ETA6002 ──┬──► SYS ──┬──► TPS62840 Buck ──► 3.3V
  VBUS   充电+路径  │          │      TPS61023 Boost ──► 5V
                    │          │
                   BATT        └──► TPS3839 欠压监测 ──► 主控 EN
                    │
              Li-Po 电池
```

| 工况 | 充电器出 | 系统吃 | 电池 |
| --- | --- | --- | --- |
| 深睡 + 充电 | 500 mA | 12.7 µA | **净充 500 mA** ✅ |
| WiFi / 音频突发 + 充电 | 500 mA | ~1.2 A | **净放 ~700 mA = 0.7C** ✅ 未超 1C |
| 离线深睡 | 0 | 12.7 µA | 放 12.7 µA ✅ |

**SYS 节点电压**：电池模式 = V_BATT（只掉路径 MOSFET 的 ~50 mV）；
VBUS 模式被内部 DCDC 稳到 3.6~4.5 V。两者都在 TPS62840 的 1.8~6.5 V 输入范围内，
**最高 4.5 V，不超 ESP32-S3 的 3.6 V 上限**（前面有 Buck 挡着）。

**★ 充电管理选 ETA6002 —— 它是这条路线的最优解**

`ETA6002` 是 `ETA6098` 的**"带电源路径版本"，同厂同源**。datasheet 原文：

> **"the charging path disconnects SYS to BATT"**（充满后电池与系统彻底断开，不微循环）
> **"dynamic power path … turns on the power-path to supplement the system load through the battery"**
> （突发超出输入能力时，自动用电池补充系统负载 —— 这就是"在线互动式"）
> Features：**"Instant on with a dead Battery or no Battery"**（无电池/死电池可立即开机）

| 项 | 值 | 页 |
| --- | --- | --- |
| 定位 | **2.5A / 3MHz 开关充电器 + 动态电源路径** | p1 |
| 效率 | up to **95%** | p1 |
| **BATT→SYS 路径 R_DS(on)** | **50 mΩ** | p2 |
| **输入工作电流（使能、未开关）** | **70 µA —— 从 VBUS 取，不花电池的电** | p2 |
| **BATT→IN 漏电（input floating）** | **0~5 µA** ← 电池侧唯一给出的数据 | p2 |
| 充电电流 | 2A @R_ISET=500Ω｜**0.5A @R_ISET=2000Ω** | p3 |
| NTC | 冷 76.5%V_IN / 热 35%V_IN 停充 | p3 |
| 封装 | **ESOP-8**（1.27 mm 间距，**可手焊**） | p1 |

**为什么它优于原方案的 ETA6098：**

| | ETA6098 | **ETA6002** |
| --- | --- | --- |
| 充电 | 开关 94% ✅ | 开关 **95%** ✅ |
| 电源路径 | ❌ **无**（缺的就是这个） | ✅ **动态路径 + 独立 SYS 脚** |
| **死电池 / 无电池可开机** | ⚠️ 未知（No-Battery detection 行为未定义） | ✅ **明确的 feature** |
| 电池侧静态 | **1 µA** ✅ | **≤5 µA**（BATT→IN 漏电） |
| 路径压降 @1A | — | **≈50 mV** |
| NTC | ❌ | ✅ |
| 封装 | DFN3x3-10 | ✅ **ESOP-8 更好焊** |
| **输入耐压** | **32 V** ✅ | ⚠️ **5.5 V** |

> **唯一取舍：输入耐压从 32V 降到 5.5V**（绝对最大 6V）。对本项目（USB-C 5V 输入）
> 不构成问题，但失去了输入高压 OVP。详见下方"USB-C 接口"一节。

**★ USB-C 输入接口：要 CC 下拉，不要 PD 诱骗**

参考设计里常见一级 **"PD 诱骗"**。**本项目不要** —— 而且理由是硬的：

> **ETA6002 的输入绝对最大额定值只有 `IN, BATT: −0.3V ~ 6V`（datasheet p2）。**
> **PD 诱骗出的 9V / 12V 会直接打穿芯片。**

就算换成能扛高压的充电器，PD 也没有收益：

1. **充电瓶颈是电池的 1C 上限，不是输入。** 1000 mAh 电池 1C = 3.7 W，
   按 95% 效率 @5V 只需约 **780 mA 输入**
2. **USB-C 默认（不做任何协商）就能给 1.5 A @5V** ⇒ **5V 够充 0.5C 甚至 1C**
3. **功放轨用不上** —— MAX98357A 上限 5.5V，本机已有 TPS61023 升出 5V
4. 对"一年充一次"的贺卡，**2 小时和 40 分钟没有体验差别**

**✅ 但必须做的是 CC 下拉电阻 —— 这是 Type-C 强制要求，不是可选项：**

| 项 | 要求 |
| --- | --- |
| 本机角色 | **受电端（sink / UFP）** |
| **CC1 与 CC2 各接一颗 5.1 kΩ 下拉到 GND** | ← **漏了它，正规 PD 充电器（尤其 C-to-C 线）根本不出电，插上什么都不发生** |
| 接上后充电器给什么 | 识别为"默认 USB 受电设备" ⇒ **5V**（USB2.0 口 500 mA / Type-C 口 1.5 A） |
| D+ / D- | 接 ESP32-S3 的 GPIO19/20，**给原生 USB 烧录用**，与供电协商无关 |

> ⚠️ **这是容易和"PD 诱骗"混淆的地方：CC 下拉是必做，PD 协商是不要。** 两颗电阻 ≈ ¥0.02。

**⚠️ 顺带说清：TVS 挡不住持续过压。**
SMAJ6.0A 的起钳位点（击穿 6.67V 起）**高于 ETA6002 的 6V 绝对最大**，
它只能挡 ESD 与热插拔尖峰，**挡不住持续过压**。
真正要挡得用开关型 OVP（datasheet 给的是同厂 `ETA7014`）。
但本机路径上**没有 PD 的 CC 握手、也没有 QC 的 D+/D- 握手** ⇒
**充电器不会主动升压，5V 是被锁死的** ⇒ 本项目倾向不加 ETA7014，用 TVS 做粗保护即可。

> ⚠️ **给复刻者的一条硬判据：如果非要改成"后备式"隔断，电池路绝不能串肖特基。**
> SS54 压降 ~0.45 V ⇒ 电池 3.65 V 时进 Buck 只有 3.25 V（< 3.3 V）⇒ Buck 进
> 100% 占空直通模式 ⇒ 1 A 突发时输出掉到 2.95 V，**低于 ESP32-S3 的 3.0 V 下限**。
> 后果：**重载欠压复位**（症状"播语音时随机重启，电量显示还健康"），
> 且固件 3.35 V / TPS3839 3.2 V / PCM 3.0 V **三道保护全部失效**。
> **电池路必须用 P-MOS 理想二极管（压降 ~0.05 V），VBUS 路才可以用肖特基。**

**⚠️ 反例：不要用"一颗升降压替代 Buck + Boost"。**
MPS MP28167-A 一颗粒能出 3V3 + 可调输出，但 **IQ = 1 mA（典型）** ——
是 TPS62840（60 nA）的 **16000 倍**，1000 mAh 电池约 38 天走完。
与 MP2615 / IP5306 同一类错误。

**⚠️ 也评估过"一颗低 IQ 路径充电器"：没有合用的。**
最接近的 TI **BQ25120A**（700 nA IQ + 集成电源路径 + Ship Mode <50 nA）——
**快充上限 300 mA、集成 Buck 输出上限 300 mA**（本项目各需 500 mA），
且 WCSP 25 球难手焊、默认输出 1.8 V。
⇒ **保持 ETA6098 + 分立 P-MOS 路径**，把 1 µA 静态电流保住。

**★ 复刻者常问：为什么不用 AXP2101？**

> **2026-10-11 补记：这条线索已被 ETA6002 取代。**
> AXP2101 想要的三样 —— 充电、电源路径、超低静态电流 ——
> **ETA6002 用一颗 ESOP-8 全给了，电池侧静态从 40 µA 量级降到 ≤5 µA。**
> 下面这份评估保留，因为它把"为什么不能用高静态电流的 PMIC"讲透了。

AXP2101（X-Powers 单节锂电 NVDC PMU）**功能最强**，一颗粒替代四颗：
充电 + **NVDC 电源路径** + 3.3V/2A Buck + 库仑计，另带 PWRON 开关机键、NTC 温度保护。

**但它的静电电流地板值是 40 µA**（datasheet Table 5-5：no VBUS, BATFET Disabled,
only RTCLDO on —— 即**最省电状态下**仍要 40 µA，而且系统轨还不供电）。
本项目 99.9% 时间要让 3.3V 轨活着供 ESP32 深睡，实际只会更高。

```
现方案   12.7 µA（乐观）→ 日耗 1.31 mAh → 21 个月
AXP2101  ≥40 µA        → 日耗 2.24 mAh → ≤12.5 个月（上限）
```

⇒ **功能全赢，但续航从 12~20 个月压到 ≤12.5 个月。** 因此本设计**首版不用**，
改用 ETA6098 + 分立 P-MOS 路径，把静态电流保住。

三条给复刻者的提醒（若你仍想用 AXP2101）：
1. **它做不出 5V** —— 线性版 DCDC5 最高 3.7V，开关版只有 4 路 DCDC。
   MAX98357A 的 5V 功放轨仍需单独一颗 Boost
2. **必须选 switch 版** —— 线性版在 500 mA 充电时耗散 **0.65 W**
   （ETA6002 开关充电仅 ~0.04 W），9 mm 封闭卡体里会热调节降流、充电变慢
3. **40 脚 QFN，手工焊接难度高** —— 建议走嘉立创 SMT 贴片

**★ 「只用 AXP2101，把其他电源芯片全省掉」—— ✅ 行**

**一颗 AXP2101 就能覆盖全部电源功能**（充电 + **NVDC 电源路径** + **3.3V/2A 主轨**
+ 欠压保护 + **E-Gauge 库仑计 SOC ±2%** + **PWRON 按键开关机** + NTC 温度保护），
**替代原来四颗**（充电 IC + 3.3V Buck + 欠压监测 + 5V Boost 那一路），
连电池分压电阻和 P-MOS 路径电路都省掉。

**唯一的代价：功放降档。** AXP2101 做不出 5V（线性版 DCDC5 最高 3.7V，
开关版最高 DCDC1 的 3.4V），功放只能吃 3.3V：

| | 5V（原设计） | **3.3V（AXP2101 方案）** |
| --- | --- | --- |
| MAX98357A 输出（4Ω） | ≈ **3W** | ≈ **1.4W** |
| 音量 | 基准 | 降约 3.6 dB（一半功率） |
| 功放接哪条轨 | 独立 Boost | **DCDC1（2A，与数字共用）**，⚠️ 别接 ALDO（只有 300mA） |

**★ 必须买【线性版】，不能买开关版 —— 而且理由很硬：**

| | 线性版 | 开关版 |
| --- | --- | --- |
| **DCDC1 出厂默认电压** | ✅ **3.3V**（Table 6-1，p22） | ⚠️ **"Customization" 定制**（Table 6-3，p19） |
| DCDC1 启动序列 | ✅ **3** | ⚠️ Customization |
| 充电热耗散 @500mA | 0.65W ⇒ 结温升 **≈19.5°C**（θ_JA=30°C/W） | ≈0.04W |

⇒ **主控要靠 3.3V 才能启动去配置 PMIC，而 3.3V 要靠 PMIC 的出厂默认值先起来。**
开关版的默认值是"定制"，标准料号可能**根本起不来**。
**线性版的 0.65W 不是问题** —— θ_JA=30°C/W 只升 19.5°C，25°C 环境 → 44.5°C，
远低于 85°C 的充电热调节阈值。

**★ 三条会影响产品行为的数据手册原文（复刻必读）：**

| 项 | 内容 | 页 |
| --- | --- | --- |

> ⚠️ **第一条是产品行为，必须写进说明书**：
> **只有电池时系统默认断电 ⇒ 开箱的卡片是"死"的，要按一下 PWRON 才亮。**
> 这既是**天然的运输模式**（出厂到用户之间系统完全断电、仓储自放电最小），
> 也**顺带解决了"要不要实体开关"**（PWRON 按键就是开关，不用在 9 mm 卡体上开滑槽）；
> **插 USB 也会自动开机**。但要告诉用户按一下，否则会以为坏了。

**库仑计默认已使能**；看门狗默认关闭。
**要注意的**：**快充默认只有 300mA**，Host 起来后需写 REG62H 改成 500mA。

> 有的说"6 µA"、"50 µA"，还有的说"QFN-24"、"支持 5.5V 升压"、"3A 开关充电"。

> **一切以 x-powers 官方 datasheet 为准。**

**★ 两层保护：第 2 层该保护谁**

| 层 | 保护对象 | 器件 | 阈值 |
| --- | --- | --- | --- |
| **第 1 层** | **电芯** | 电池自带 PCM | 过放 3.0V / 过流 / 短路 |
| **第 2 层** | **下游系统** | **TPS3839** + 主控 EN | **3.2V 发复位** |

**第 2 层不是"再保护一次电芯"**（那只是冗余 + 双重压降），而是**保护系统**：
电池跌到 3.0V 时 PCM 硬切，但**电容残压还在** —— 主控可能在电压不稳区间乱跑，
写坏 NVS、弄坏 SD 卡 FAT。第 2 层在电池彻底趴下前**稳定宣告断电**，给主控收尾时间。

| 第 2 层候选 | 静态电流 | 评价 |
| --- | --- | --- |
| **TPS3839**（TI） | **~250 nA** | ✅ 首选，纳安级 |
| **S-808 / S-809**（精工） | ~1 µA | ✅ 够用，国内易采 |
| ~~DW01A + FS8205A~~ | 3~5 µA | ❌ 不作第 2 层（纯冗余 + 双重压降） |

**★ 电源架构：5V + 3.3V 双轨**

本机绝大多数器件吃 3.3V，**5V 只用在两处**：USB 输入、以及给 MAX98357A 功放供轨。

```
USB-C 5V ──┬──► ETA6098 ──► Li-Po 3.0~4.2V
           │                     │
           │             ┌───────┴────────┐
           │             ▼                ▼
           │      【TPS62840】       【TPS61023】
           │      Buck → 3.3V        Boost → 5V
           │        IQ 60nA            IQ 1µA
           │           │                 │
           └─(VBUS)───►│                 └──► MAX98357A
                       ▼
         ESP32-S3 / 屏 / I2C 全部 / SD 卡
```

| 位置 | 推荐 | 关键参数 |
| --- | --- | --- |
| **3.3V 主轨** | **TPS62840** | Buck，**IQ 60 nA**，750mA，**输入 1.8~6.5V** |
| | 备选 TPS62842 / MP2161 | 1A / 2A（MP2161 IQ ~17 µA 偏高） |
| **5V 功放轨** | **TPS61023** | Boost，**IQ 20 µA**，1A，**输入 0.5~5.5V** |
| | 备选 TPS61022 | IQ 3 µA，2A |
| | ~~MT3608~~ | ❌ IQ ~100 µA，且需外部补偿 |

**关于"简单易用"：** 这两颗都不难焊，也不需要外部补偿或配环路 ——

| | TPS62840 | TPS61023 | 对比：ETA6098 |
| --- | --- | --- | --- |
| 封装 | **SOT-23-6** | SOT-563（2×2 mm） | DFN-8 |
| 外围 | 1 电感 + 3 电容 | 1 电感 + 2 电容 | 3 电阻 + 3 电容 |
| 外部补偿 | ❌ 内部补偿 | ❌ 内部补偿 | — |

⇒ **照 datasheet 的固定外围值抄即可，不需要计算。** TPS62840 是 SOT-23-6，
焊接难度与 ETA6098 同级。

**⚠️ 唯一的坑：`EN` 引脚必须加 100 kΩ 下拉到 GND。** 主控深睡时 GPIO 变高阻，
`EN` 悬空会让 DC-DC 处于不确定态。TPS61023 的 `EN` 由主控 GPIO33 驱动，
深睡时拉低关断功放轨（详见下方睡眠与唤醒）。

**⚠️ 反直觉但关键：这里不能用 LDO，哪怕它最"简单"。**

| | AMS1117 类 | 低 IQ LDO | **TPS62840 Buck** |
| --- | --- | --- | --- |
| 静态电流 | **~5 mA** ❌ | ~1.6 µA | **60 nA** ✅ |
| 效率（3.7→3.3V） | ~89% | ~89% | **90%+** |
| 电池 < 3.4V | 压差不足，**跌出稳压区** | 同样跌出 | ✅ 工作到 3.0V |

> **AMS1117 的 5 mA 静态电流会把 12~20 个月续航砍到几天** ——
> 与本机 50 µA 级的整机待机假设差 100 倍。低 IQ LDO 解决了静态电流，
> 却解决不了**压差**。⇒ **Buck + 低 IQ 是唯一正解**，外围只需 1 电感 + 3 电容。

**★ 睡眠与唤醒：电源管理怎么和它长在一起**

低功耗不是一个功能，是**三条独立路径**的组合 —— 器件已齐，不需要额外加芯片。

**路径一 · 深睡时主动关掉非必需轨**

| 轨 | 深睡时 | 怎么控 |
| --- | --- | --- |
| **3.3V（TPS62840）** | **保持开启** | 不控，空载 IQ 仅 60 nA |
| **5V（TPS61023）** | **主动关断** | 主控 GPIO33 拉低 `EN`，功放**彻底断电**（不是待机） |

```
进深睡前：  GPIO33(5V_EN) = 0  →  TPS61023 关断，5V 轨消失
唤醒之后：  GPIO33(5V_EN) = 1  →  等 5~10 ms 软启动，再初始化 I2S / 放音
```

**路径二 · 三个唤醒源**（都必须落在 **RTC GPIO 域**，ESP32-S3 为 GPIO0~21）

| 唤醒源 | 引脚 | 触发 | 用途 |
| --- | --- | --- | --- |
| **按键 KEY1** | GPIO1 | 低电平 | 用户按一下开机 |
| **PCF8563 INT** | GPIO14 | 闹钟拉到低 | 定时提醒、定时翻页刷贺卡 |
| **CHG_DET（ETA6098）** | GPIO21 | 插 USB 变电平 | **插上充电自动开机**，显示充电状态 |

```c
esp_sleep_enable_ext1_wakeup(
    (1ULL << 1) | (1ULL << 14) | (1ULL << 21),   // KEY1 | RTC_INT | CHG_DET
    ESP_EXT1_WAKEUP_ANY_LOW
);
gpio_set_level(5V_EN, 0);
esp_deep_sleep_start();
```

唤醒后**先读 `esp_sleep_get_wakeup_cause()` 分流**：按键 → 立即出画面；
闹钟 → 静默刷新；插电 → 显示充电进度。三者开机流程不同，**不能共用入口**。

**路径三 · TPS3839 不是唤醒源，是"强行拉闸"**

```
≥ 3.35V   固件读 ADC 发现低电量 → 主动进 Deep Sleep   （软防御，最早）
   3.20V   TPS3839 /RESET 拉低主控 EN → 硬断电        （硬防御，兜底）
   3.00V   电芯自带 PCM 切断                          （最后一道）
```

**固件那层必须比硬件早触发**（3.35V 就主动睡），好让主控有时间给 NVS / FAT 收尾；
**TPS3839 是兜底** —— 固件卡死或根本没跑起来时还有它；**PCM 只管电芯自己**。

> **⚠️ 接线必须注意：TPS3839 是漏极开路输出。**
> `/RESET` 拉低时是"吸电流到地"，所以**必须配 100 kΩ 上拉到 3.3V**。
> 少了这颗上拉，EN 会悬空，主控行为完全不确定。

```
3.3V ──[100kΩ]──┬── ESP32-S3 EN
                ├── TPS3839 /RESET   （漏极开路，低有效）
                └── 100nF 对地       （上电复位延时，防抖）
```

**⚠️ 别把 IP5306 那类"充电宝 SoC"当替代方案。** 它集成度高
（充电 + 升压 + 保护 + 电量显示），但**静态电流 50~100 µA** ——
本机整机待机假设才 50 µA 量级，**一颗芯片就能把 12~20 个月的续航砍到几个月**。
这不叫"外围多一点的方案"，是选型方向错误。

**电池自带保护板怎么确认？** ① 目视：电池一端有约 15 × 3 mm 细长小 PCB；
② 万用表：红黑线两端正/反向电阻都应在几百 kΩ 以上，若某方向低到几十 Ω 即带保护板。
**若买的是裸电芯（无保护板），必须换带 PCM 的型号，不要自己加。**

**⚠️ 过流风险（P1，复刻时必须注意）**

这颗电池最大放电只有 1C = 1000 mA，而本机峰值电流刚好卡在这条线上：

```
ESP32-S3 + WiFi 发射峰值            ≈ 350 ~ 500 mA
MAX98357A @3.7V / 4Ω 满音量        ≈ 600 ~ 700 mA
────────────────────────────────────────────────
两者同时发生（AI 回答 + 语音播报）   ≈ 1000 ~ 1200 mA  ← 已超 1C
```

后果是 PCM 触发过流保护、**整机瞬断重启**，典型症状为"放语音放到一半死机"，
而且用 USB 供电测试永远复现不了。对策：

1. 电池输入端并一颗 **220~470 µF 低 ESR 电容**（钽或固态），吸收音频瞬态 ——
   最有效，但**要在画 PCB 之前预留位置**。
2. 固件限制最大音量，WiFi 发射功率按需降到 11 dBm 以下。
3. 仍触发则换 1.5C 放电能力的 502080。

### 3.5 结构

**外形尺寸：62 × 102 × 9 mm**（竖版）

- 面内尺寸：屏 53 × 92.99 mm 居中，四周留 4~5 mm 边框。
  长宽比 1.65，与标准名片（54 × 90）基本一致 —— **面内就是名片的体感**。
- **厚度 9 mm**：502080 电池单体就有 5.0 mm 厚，必须完整计入。

| 层 | 厚度 (mm) | 说明 |
| --- | --- | --- |
| 亚克力盖板 | 0.5 | 屏窗 |
| 墨水屏（含胶层） | 1.1 | 规格书标 0.90 ~ 1.0 |
| 间隙 | 1.4 | 让给 PCB 正面的低矮元件 |
| PCB 与电池同层 | **5.0** | 电池占满这层厚度，PCB 在电池周围环绕 |
| 背盖 | 0.5 | 3D 打印或亚克力 |
| **合计** | **8.5 ~ 9.0** | 预留装配公差后取 9 |

**关键结构决策：电池要嵌进 PCB 的镂空槽、与 PCB 同层，不能叠放。**
若按常规叠放（屏 → 元件 → PCB → 电池 → 背盖），总厚会到 10.5 mm 以上。
开槽方案下，电池 20 × 80 mm 走卡体中央，两侧各留 21 mm 作 PCB 元件区 ——
这块区域正好落在屏的可视区之后，完全看不见。

- 屏窗：亚克力盖板 + 一圈黑色泡棉遮光。屏是玻璃基板，
  **盖板必须留 0.3~0.5 mm 让位**，不能直接压在屏面上。
- **重量预估约 50 g**（屏 8.5 + 电池 ~19 + PCB ~10 + 盖板背盖 ~8 + 元件 ~5）。
  对外说"卡片"，实际手感是"薄型电子设备"，请以此为准。
- 不做实体电源开关 —— **插电即充、拔电即睡**，减少一个用户要理解的概念。

### 4.3 中文显示的关键决策

墨水屏不适合实时渲染矢量中文字。方案：

- **字库裁剪**：从思源宋体 / 文泉驿提取常用 3500 字，转 16×16 点阵，
  体积约 300~600KB，放进 `storage` 分区。
  **240×416 下 16×16 正好一行 15 字、一屏 26 行**，是这个分辨率的最优档位。
- **图文渲染在别处做**：手机端把"标题 + 正文 + 配图"排版好，转成 1-bit 位图推给设备，
  设备端只负责搬运和刷屏 —— **这是让这台设备"看起来聪明"的最省力办法**。

### 4.4 刷新策略（墨水屏的性能生死线）

**✅ 颜色版本已确认为黑白（B/W）。**

**先说一件采购时会踩的坑：本款屏有两个厂牌编号，是同一块屏。**

| | 编号 |
| --- | --- |
| 兴泰（SEEKINK，江西） | `HINK-E037A03-A1` |
| Good Display（大连佳显） | `GDEQ037T31` |

同一批 EPD 屏体的不同分销渠道（Adafruit / Pimoroni / Elecrow 在卖的也是它）。
尺寸、分辨率、驱动 IC（**UC8253**）、24-pin FPC、有效区与外形毫米数**逐项吻合**。
⇒ **买哪个编号都是同一块屏**，且本款屏有英文公开资料可查。

**刷新能力（有出处，非类推）：**

- Elecrow 模组规格表：**Refresh Mode — Partial refresh（省电）** ⇒ 官方支持局刷
- CalEPD 项目实测记录：**"refreshes twice as fast and has also a special fast mode"**
  ⇒ 比同类 EPD 快一倍，另有专门快刷模式

规格书**未给刷新时间**。下表是**同类屏参考值**（非本款规格书数据），
仅用于说明黑白与三色差一个数量级：

| 屏 | 颜色 | 全刷 | 快刷 | 局刷 |
| --- | --- | --- | --- | --- |
| **3.1" GDEQ031T10（同类黑白屏，参考）** | **B/W** | **3 s** | **1 s** | **0.5 s** |
| 3.7" GDEY037Z03（同类三色屏，差异来源） | B/W/R | 16 s | 11 s | 1.5 s |

⇒ **黑白版 + 官方局刷支持 ⇒ 延迟落在"用户感觉不到等"的区间**，
这是能同时做电子书、实时听记、界面小改的前提。复刻时请认准黑白版 ——
换三色版，这些功能大半要砍。

本项目刷新预算（保守取值，实测后收紧）：

| 场景 | 模式 | 耗时 |
| --- | --- | --- |
| 翻页阅读 / 界面小改 | 局刷（partial） | **≤ 0.5 s** |
| 换卡片 / 切模式 | 全刷 + 消影 | **≤ 3 s** |
| 深睡唤醒后首刷 | 全刷 | **≤ 3 s** |

> **体验代价比想象中小。** 3 s 全刷仍需设计兜住：
> - 切模式给 **UI 反馈**（屏上先出"加载中"，或一颗状态 LED），避免"以为死机"
> - **贺卡 / 名片这类静态内容优先** —— 一天只刷一次，感受不到慢
> - 电子书靠局刷撑体验，全刷只在合上 / 打开时插一次

**两条直接推论：**

- **实时字幕按「语义句」刷新，而不是逐字。** 局刷 0.5 s 物理上追得上语速，
  但逐字刷会把频次拉到每秒数次、明显加速屏体老化，而收益极低 ——
  人在听语音时本来就不逐字读屏。按句刷把频次压到每分钟 15 ~ 20 次，
  **这是主动选的节奏，不是被迫接受的妥协。**
- **画面上限是 16 级灰度，没有第三种颜色。** 节日氛围由**卡面 PCB 丝印**提供
  （见丝印那道工序），配图靠灰度 + 抖动做层次。

- 每 N 次局刷强制插一次全刷，消除残影（否则一个月后屏幕上会叠出"鬼影"）——
  这也是厂商自己的操作建议（同 IC 屏产品页原文：连续 5 次快刷 / 局刷后做一次全屏刷新）
- 刷新期间 BUSY 引脚拉低，主控**必须等待**而不是轮询空转（省电）
- **刷新次数寿命：规格书未给，需向厂商 FAE 索取或自行实测。**
  好消息是它**不再是设计阻塞** —— 黑白版 0.5 s 局刷让刷新频次本身就低，
  不必为省次数牺牲交互体验。可查证的只有定性结论：**频繁刷新会加速老化。**

## 七、复刻须知与已知风险

**复刻前请先核对这几条，能省掉大量返工：**

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **认准驱动 IC 是 UC8253** | 同尺寸 3.7" 屏另有 IST7163 方案，**命令集不通用**，买错屏直接点不亮。本款屏官方规格写作 "UC8253C"（尾部 C 为 IC 版本代号，型号即 UC8253） |
| 2 | **24-pin 引脚定义** | 已按官方规格书第 6 节逐脚核对，全表见 `docs/datasheets/README.md`。**不要照抄别家参考电路** |
| 3 | **屏断电时序厂商未定义** | 规格书通篇无 power-off sequence，屏带 VCOM/VGH/VGL 高压。**正确做法是 VDD 常接、用命令让屏进深睡**（≤3 µA），不要自己加 MOS 切屏电 |
| 4 | **全刷是秒级，不是瞬时** | 同类黑白屏参考 ≤3 s，本款另有 fast mode。属物理特性不是故障，UI 必须接住（见 4.4） |
| 4b | **别看引脚 5 就以为屏是三色** | UC8253 原生支持黑白红，`VDHR`/`VSH2` 引脚（红色专用电压）**在黑白版上照样存在**。**判断颜色版本只能看实物标签** |
| 5 | NT3H2111 无源 NFC 与屏背板的电磁干扰 | 需实测验证，布局时让 NFC 天线远离屏的升压电路 |
| 6 | 墨水屏刷新寿命 | **规格书未给**，需向厂商 FAE 索取或自行实测 —— 它直接决定高频刷新场景（实时字幕、秒显时钟）能否成立。可确定的只有定性结论：残留影像真实存在，局刷必须定期插全刷消影 |
| 7 | **电池 1C 放电上限** | 音频 + WiFi 同时满负荷会超 1C 触发保护，须在电池端并 220~470 µF 缓冲电容，见 3.4 |
| 7b | **充电 IC 不带过放保护** | ETA6098 只充电。过放 / 过流 / 短路**依赖电池自带 PCM**；第 2 层加 **TPS3839** 欠压监测（IQ ~250 nA）在 3.2V 拉主控 EN 收尾。见 3.4 |
| 7c | **不可用 LDO 做 3.3V 稳压** | **AMS1117 静态电流约 5 mA**，会把 12~20 个月续航砍到几天；低 IQ LDO 又有压差问题（电池 <3.4V 跌出稳压区）。**必须用 Buck：TPS62840（IQ 60 nA，输入 1.8~6.5V）** |
| 7d | **5V 轨只有功放用** | MAX98357A 供 5V 可出更大音量，用 **TPS61023**（IQ 20 µA）升压。**不要用 MT3608**（IQ ~100 µA） |
| 7e | **充电 IC 不要换 MP2615** | MP2615 静态 **1.1 mA**（是 ETA6098 的 1100 倍），会把续航从 12~20 个月砍到约 1 个月。它的宽幅输入（4.75~18V）对 USB 5V 输入用不上。**保持 ETA6098** |
| 7f | **DC-DC 的 EN 必须加 100 kΩ 下拉** | 主控深睡时 GPIO 变高阻，`EN` 悬空会让 DC-DC 处于不确定态。TPS61023 的 EN 由主控 GPIO33 驱动，深睡拉低关断功放轨 |
| 7g | **TPS3839 是漏极开路输出** | 接主控 EN **必须配 100 kΩ 上拉到 3.3V**，否则 EN 悬空、主控行为不确定。见 3.4 |
| 7h | **唤醒引脚必须在 RTC GPIO 域** | ESP32-S3 的 RTC 域是 GPIO0~21。按键 / RTC INT / 插电检测三个唤醒源都要落在此域内，GPIO42~48 段不行 |
| 7i | **ETA6098 没有电源路径管理** | 回原始 datasheet 核对：**无 power path、无 SYS 引脚**。中文站流传的"内置 DPM"是错的。`PMID` 只是 OVP 后的中间节点（接 22 µF 到地），不是系统取电口 |
| 7j | **`STAT` 脚是开漏输出** | 充电时拉低、充满后高阻。作唤醒源**须配 10 kΩ 上拉**（datasheet 图用 1 kΩ，太耗电） |
| 7k | **电池与系统的关系选「在线互动式」** | 电池常挂系统节点、充电器并联补差。**不做后备式隔断**（会把电池的 1 A 峰值缓冲切掉）、**不做纯在线式**（电池持续微充微放折寿）。⇒ **不需要任何 OR 电路**。见 3.4 |
| 7k2 | **若改成后备式隔断，电池路禁用肖特基** | SS54 压降 ~0.45 V ⇒ 电池 3.65 V 时进 Buck 仅 3.25 V ⇒ 直通模式下 1 A 突发掉到 2.95 V（ESP32-S3 需 ≥3.0 V）⇒ **重载欠压复位，且三道保护全部失效**。电池路必须用 P-MOS 理想二极管 |
| 7k3 | **ETA6098 的「No-Battery detection」行为未定义** | datasheet 只列了这个 feature 名字，**正文一句话都没有**。需确认"检测到无电池时是停输出还是维持 CV" —— 前者会让**不接电池调试**和**电池被 PCM 切断后插 USB** 上不了电。**优先问 FAE，其次实测** |
| 7k4 | **充电管理选 ETA6002 而不是 ETA6098** | ETA6002 = **开关充电 95% + 动态电源路径 + 独立 SYS 脚 + 无/死电池可开机 + 50 mΩ 路径 MOSFET + NTC + ESOP-8 可手焊**，同厂同渠道。唯一取舍：**输入耐压 32V → 5.5V**。见 3.4 |
| 7k6 | **USB-C 的 CC 下拉电阻不能漏** | **CC1 / CC2 各一颗 5.1 kΩ 下拉到 GND** —— Type-C 受电端的**强制要求**。漏了它，正规 PD 充电器（尤其 C-to-C 线）**根本不出电**。**注意别和"PD 诱骗"搞混：CC 下拉是必做，PD 协商是不要** |
| 7k7 | **不要加 PD 诱骗** | **ETA6002 输入绝对最大只有 6V**（datasheet p2），PD 诱出的 9V/12V **会直接打穿芯片**。且无收益：充电瓶颈是电池 1C 上限（5V 已够），功放上限 5.5V（已有 Boost） |
| 7k8 | **TVS 挡不住持续过压** | SMAJ6.0A 起钳位点 6.67V **高于芯片 6V 绝对最大**，只能挡 ESD 与尖峰。真 OVP 需开关型（同厂 `ETA7014`）。但本机**无 PD/QC 握手电路 ⇒ 输入锁在 5V** ⇒ 倾向不加 ETA7014 |
| 7k5 | **ETA6002 的电池侧静态电流要实测** | datasheet 只给了 **BATT→IN 漏电 0~5 µA**，没给"电池侧总消耗"。架构上必然很低（芯片由 IN 引脚供电），**但数值待测**。⚠️ **别把 70 µA 当电池消耗 —— 它是从 VBUS 取的** |
| 7l | **不要用一颗升降压替代 Buck + Boost** | MPS MP28167-A 的 **IQ = 1 mA**，是 TPS62840（60 nA）的 **16000 倍**。与 MP2615 / IP5306 同一类错误 |
| 7m | **路径保护的 TVS 要换** | 参考设计里的 SMAJ15CA（15 V）是 **12 V 系统遗留物**，在 5 V 轨上钳位点约 24 V，形同虚设。应改 **SMAJ6.0A** |
| 7n | **为什么不用 AXP2101** | ✅ **该结论已推翻（2026-10-11 晚），见 7p —— 用 AXP2101 反而更优。** 原判断依据"40 µA 会打穿续航"，但那是我自己造的"一年"目标 |
| 7p | **★ 只用 AXP2101（单芯片电源）→ 行** | 用户真实目标是**静态 1 个月** ⇒ AXP2101 的 8.6~12 个月是目标的 **8.6~12 倍**，原反对理由作废。**一颗替代原四颗**（充电 + NVDC 路径 + 3.3V/2A + 欠压 + **库仑计 SOC ±2%** + **PWRON 按键** + NTC），连分压电阻和 P-MOS 路径都省掉。**唯一代价：功放 3W → 1.4W**（做不出 5V） |
| 7p2 | **★ 必须买【线性版】，不要开关版** | **线性版 Table 6-1（p22）DCDC1 出厂默认 = 3.3V、序列 3**；**开关版 Table 6-3（p19）默认电压栏写 "Customization"** ⇒ 标准料号可能**起不来主控**。线性版 0.65W 热耗散 × θ_JA 30°C/W 只升 **19.5°C**，**不是问题** |
| 7p3 | **★ AXP2101 有"运输模式"，说明书写清楚** | **p18 §6.5.2：只有电池时 BATFET 默认断开**，须**按 PWRON 或插 USB** 才开机 ⇒ **开箱的卡片要按一下才亮**。这是天然运输模式（仓储自放电最小），也顺带替掉实体开关；但**不写说明书用户会以为坏了** |
| 7p4 | **欠压关机阈值用 REG24H 设 3.3V** | **p36：V_OFF 可设 2.6~3.3V（0.1V/step）**，默认 2.6V。设 3.3V 即替代原设计的欠压监测 IC |
| 7p2 | **宣传语需同步改** | 「3W 喇叭」→ **1.4W**（或去掉功率数字）。本稿内 2 处、README 内 4 处提及，方案定案后统一改 |
| 7q | **★「AI 听记 1.5 天」必须压电流** | 65 mA 只能撑 **13 小时**，离 1.5 天（36 h）差 **2.75 倍**，需压到 **≤23.6 mA**。手段：帧间浅睡（Opus 嵌入式版每秒仅 83 ms CPU）、降采样率/码率、SD 攒批写。**不确定能做到，须实测**。这是目标确认后**剩下的唯一瓶颈** |
| 7o | **网上的 AXP2101 二手资料不可信** | 流传的"深休眠 <1 µA / 6 µA / 50 µA"、"QFN-24"、"支持 5.5V 升压"、"3A 开关充电"**全部与官方 datasheet 矛盾**。**以 x-powers 官方 datasheet 为准** |
| 8 | **PSRAM 深睡电流** | 2 MB Quad 标称 40 µA，是整机待机假设的 3 倍。深睡必须确认 VDD_SPI 已断电，首板点亮后实测 |
| 9 | **别指望语音唤醒常开** | 唤醒词检测约 15 mA，1000 mAh 只够撑 2.7 天（比深睡待机耗电 300 倍）。**助手必须按键触发**，见 2.6 |
| 10 | **Opus 编码必须用嵌入式版** | 标准 libopus 在 ESP32-S3 上编码 1 秒语音需 420 ms CPU，嵌入式版仅 83 ms。参数用 COMPLEXITY=1 + 关闭 VBR |
| 11 | **实时与分时是两条链路，别用一条硬扛** | 实时（插电）走流式上传；分时（电池）走批量上传 + 分段重传。长录音若硬走流式，会因网络抖动断流 |
| 12 | **TF 卡的 FAT 保护与大块顺序写** | 写入量不是问题（Opus 下折合 600 年），**FAT 损坏与写放大才是**。对策：append-only、分段文件、掉电预警、32~64 KB 缓冲顺序写。见 2.5 |
