# lighting OS 五层架构 v0.3

关联 immml/E-paper-card#1。本文为设计草案，不是冻结的 API 或 Flash 分区表。测试范围见 [需求规格书](需求规格书.md)，实物限制见 [硬件核实表](硬件核实表.md)。

| 层 | 职责 |
|---|---|
| 5 应用层 | 图片、MP3、AI、设置、lighting OS App Store、第三方 Python App；配套手机端 BLE App。 |
| 4 用户层 | 按键导航、墨水屏 UI、四键密码与权限授权、lighting OS App Manager、lighting OS Python Runtime。 |
| 3 固件层 | ESP-IDF FreeRTOS 和系统服务；官方 Bootloader；CH32 管理固件负责按键、电源、PMIC、状态灯、马达和救援。 |

## 服务与运行约束

System Manager 管生命周期；Power/Input 由 CH32 提供底层事件；Display/Audio/Storage/Device 分别拥有外设；App/Security 执行安装和授权；Network/OTA/Cloud 管连接和更新。任务与服务不要求一一对应：电源事件、音频和存储采用有界队列、超时与反压，显示刷新、下载不阻塞输入；优先级、核心亲和性和栈大小由实测决定。音频 DMA 等使用满足外设约束的内存；PSRAM 用于图片、解码及 VM 的可迁移缓冲区。并发压力测试包含 Wi-Fi/BLE、TLS 握手、音频、显示和 Python，记录内部堆最低水位、最大连续块、任务栈水位和断音。

共享总线 B 由 ESP 统一调度，CH32 管理端点优先服务；关键消息采用 CRC（检错）、序列号和独立密钥认证（防伪造），并建立跨重启防重放规则。认证、代码尺寸和时延须在 CH32 验证，不以 CRC 代替鉴权。共享总线被占用时不能保证可用性，物理 Kpower 与 CH32 本地电源流程不依赖 ESP 或扩展模块。第三方仅访问受管设备句柄，不提供可绕过板载地址限制的原始总线。被动模块用户授权后使用；主动模块身份采用 ECDSA、ECDH、HKDF 与 AEAD 会话，并拒绝重放。主动认证失败不得自动下载、执行或获受信权限；仅在明确授权且能力受限时按被动模块处理。无已验证的热插拔电气支持时，要求断电插拔。远程和 AI 指令统一经本机权限检查。

## 应用、存储及恢复

保留 `/lightingOS/{apps,system,python,data,media,cache,packages,config,logs}/`。TF 卡不承担启动信任根；安全卸载，异常后只读诊断，修复或格式化须确认。`.lpk` 候选容器为 ZIP，`manifest.json` 描述入口、依赖、权限、API/系统版本及硬件兼容性；签名覆盖清单与每个文件的哈希。安装到临时位置，限制展开尺寸和条目数，拒绝越界或重复路径，验证后才激活；启动时清理未完成事务并保留上一可用版本。卡上的受信 Python 内容在执行前复验。MicroPython 首版单实例、有界堆/执行时间和应用目录；移除裸 `machine`、原生扩展等绕过通道。不是硬件级恶意应用隔离；在隔离验收通过前不开放不受信任的应用执行。四键密码采用带盐 KDF、持久化限次锁定和敏感操作再确认，不作为设备身份或加密主密钥。

Flash 按 16 MB 规划双 OTA 槽、otadata、配置/证书、诊断与系统资源；容量、偏移和是否增设救援镜像按首次链接与增长余量核算。应用 OTA 通过 HTTPS 下载并校验兼容性、SHA-256、签名及策略后切换槽；启动自检不应因 TF 或云端不可用误回滚。ESP32 救砖采用 CH32 控制 GPIO0/EN 的 ROM USB 路径；生产 Secure Boot、加密与 eFuse 下载策略必须先验证兼容，另行授权。二级 Bootloader 不作为常规 OTA 对象。CH32 优先独立 SWIO 烧录/恢复，不承诺双槽或远程更新。

## 云与信任

lighting OS Cloud 使用 Node.js/TypeScript 生态：共享基于 Fetch API 的业务入口，Cloudflare Workers 与 Docker/Node 使用各自的入口和存储适配器；不得假定 Workers 支持完整 Node API、持久文件系统或后台常驻进程。先做两环境契约测试。HTTPS/TLS 1.2/1.3 使用 mbedTLS 客户端；验证服务端身份后用一次性激活码及设备生成的 P-256 CSR 绑定，签发设备证书并使用短期令牌。私钥不出设备，证书签发和密钥轮换单独设计，不把 CA 私钥放进通用发布容器。远程命令签名绑定设备、操作、时间戳和 nonce；重放状态、时钟失效和权限拒绝纳入验收。

设备预置 lighting OS 根公钥；App、驱动、固件按用途授权签名者，OTA 与 App 不共用密钥。发布签名链和 ESP-IDF Secure Boot 镜像验证分别配置，不能互相替代。云端提供分类索引、更新元数据、断点续传和同步；增量分发后评估。设备保留本地决定权，BLE 配网仅在物理确认后的短时窗口开放，凭证不记日志。

固件与后端 AGPL-3.0-or-later。已获批准的候选包括 ESP-IDF、LVGL、MicroPython、图片/MP3 解码组件、esp_codec_dev 与 WCH 工具链方案；锁定版本后逐项审核许可证和分发义务，本阶段未引入依赖。
